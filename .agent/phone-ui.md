# Phone SPA (`mobile/`)

## Files

| File | Role |
|---|---|
| `index.html` | shell, inline SVG sprite, pairing/chat markup, `?v=<n>` asset refs |
| `app.js` | transport, state, all screens/sheets, markdown renderer, highlighting, PWA/voice/push/share |
| `styles.css` | tokens, light/dark, layout, components, safe areas, reduced motion |
| `sw.js` | shell cache (`dsh-remote-v<n>`), navigation fallback, push handlers, diagnostics POST |
| `manifest.webmanifest`, `favicon.svg`, `icons/` | installable PWA |
| `mock-server.js` | dev-only protocol mock (not served by the plugin) |

No framework, no build step, no CDN, no inline scripts (CSP `script-src 'self'`). Inline styles
are allowed. Everything is served by the plugin server, not the DSH web server.

## State and transport

- `S` is one global state object (connection, sessions/workspaces, active session, transcript,
  queue, approvals/questions, sheets, push, app lock).
- `sendFrame()` sends JSON over the WS; `onFrame()` dispatches by `type`. Unknown types are
  ignored so newer Hosts can add frames.
- Reconnect uses backoff plus a ping watchdog and visibility-aware fast resume. A hidden page
  reports `client.visibility false` so the Host sends pushes; visible pages do not.
- Pairing: token link (`?t=`) or PIN; cookie auth; unpair from the menu.

## Sheets

All sheets go through `openSheet(kind)` → `buildSheet()` (clears the body then dispatches).
**Never call a sheet builder directly after an async frame** — the body is appended to and a
loading spinner can survive under loaded rows (this was the old "Commands buffering" bug).
Asynchronous handlers rebuild via `buildSheet()`.

Sheets: sessions, new-session, model, reasoning-effort, preset, message actions, menu, attach,
rename, queue item/edit, diff, commands, command-input, plus dialogs (question/approval/lock).

## Sessions sheet (v20)

- Grouped by the Host's project workspaces (`workspaces` frame order) with a collapsible header
  (title, root path, count, folder glyph) and an **Ungrouped** section for sessions with
  `workspaceId: null`. Collapsed ids persist in `localStorage["dsh-remote-projects.v1"]`.
- Archived sessions are **hidden by default**; a **Show archived (N)** control reveals them inside
  their project (grayed, tagged); **Hide archived** hides them again. They open read-only with an
  unarchive banner.
- Pinned sessions lead inside a section (stable sort). Search filters rows, forces project bodies
  open and hides empty sections.
- New-session sheet offers preset rows, project chips (fills the working directory) and a free-text
  cwd with recent-cwd chips.

## Commands sheet (v20)

- Rows show `/name`, description (2-line clamp) and the argument hint on its own line.
- Hinted commands open a **command-input** sheet (hint as placeholder, Run command) and execute
  `commands.execute { line: "/name <args>" }`.
- Un-hinted commands keep the double-tap confirm and execute the bare `/name`.
- A lost list reply times out after 10 s with a retry message (no infinite spinner).
- The sheet only shows what the bridge allows: `/export` and `/permission` never appear.

## Chat, approvals, questions

- Streaming assistant text/reasoning, collapsible tool cards and step activity.
- Approval cards show bounded, secret-scrubbed context (`argsPreview`, `argsKind`, `detail.path`).
  Questions render radio/checkbox/custom answers with a timeout state.
- Cross-session pending interactions appear in a notice bar with an **Open** action; a card only
  renders in its owning session.
- Queue strip supports edit/remove/steer and Queue vs Steer for the next send.

## Versioning / caching

Shell changes need **both** numbers bumped together:

- `index.html`: `/styles.css?v=<n>`, `/app.js?v=<n>`
- `sw.js`: `CACHE = 'dsh-remote-v<n>'` and the matching PRECACHE URLs
- `mobile/app.js`: no shell version (it reads the Host's `version` frame; `FALLBACK_VERSION` is the
  package version)

`dev/spa-check.mjs` enforces agreement. The page reloads at most once when a new SW activates;
after a deploy, the phone may need one refresh (or close/reopen) to pick up the new shell.

## Screenshots / README images

`docs/screenshots/` is generated by `dev/capture-screenshots.mjs` from the mock server at
390×844 @2x: pairing, sessions grouped by project, chat, commands. The README references them via
raw GitHub URLs so they render on both GitHub and npm; `package.json` includes the PNGs.
Never publish screenshots of a live Host (they would contain real session titles/paths).

## SPA checks

- `dev/spa-check.mjs`: undefined helper calls, cached DOM ids present in `index.html`, version refs
  coherent.
- `dev/ui-check.mjs`: live headless-Chrome assertions for grouping/archived/commands and zero
  console errors.
- `dev/layout-probe.mjs`: no horizontal overflow at 320/360/390/412; header title and footer
  context meter centred (`titleCenterOffset`/`meterCenterOffset` ≈ 0).
